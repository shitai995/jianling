# 内容扩建与配置指南

更新：2026-10-22。适用于 `UnityProject`，Unity 2022.3.62f3。所有内容编辑都在退出 Play 后进行；本批未打包。

## 入口与保存原则

| 内容 | Unity 菜单或资产 |
| --- | --- |
| 统一查找与定位 | 古剑 → 内容 → 内容工作台 |
| 武器、道具、技能、敌人 | 古剑 → 内容 → 武器道具技能敌人配置 |
| 新建及扩建瓦片地图 | 古剑 → 内容 → 瓦片地图编辑器 |
| 原版动作草稿、预览与发布 | 古剑 → 内容 → 动作编辑器 |
| 地图事件索引 | 古剑 → 内容 → 生成地图事件资产（保留剧情原文） |
| 出口、入口、NPC 回调 | 内容工作台 → 地图 → 编辑出口 / 入口 / NPC 事件 |
| 数据库 | `Assets/Resources/OriginalDatabase.asset` |
| 地图／阶段／角色目录 | `Assets/Resources/OriginalAssetCatalog.asset` |

原版记录继续保留在基线数组；新增内容放入 `addedEquipment / addedItems / addedSkills / addedEnemies / addedSprites / addedStages`。运行时读取入口自动合并两者，扩展表不是另一套游戏系统。编号在各自表内唯一；敌人编号还需与精灵编号配套。

常规步骤：选择现有模板 → 填写未使用的新编号 → 点击“复制选中模板到扩展内容” → 修改字段 → “校验并保存配置”。复制会保留模板的规则与动作引用；道具会生成并保存图标和掉落 Prefab，敌人会复制并登记角色 Prefab。正式数据库不预装测试编号9001～9005。

“从原版 JSON 导入数据库”现在只按编号／剧情标识补缺失的原版记录，保留已有数值、规则和扩展内容；成长表仅在空表时初始化。原 JSON 用于核对和补缺，不再整表覆盖手工编辑。修改普通字段后保存即可；Play 中的修改不作为正式配置。

## 精灵动作编辑与发布

从“内容工作台 → 精灵 → 编辑动作”或“古剑 → 内容 → 动作编辑器”打开动作窗口。选择已有精灵配置后，工具从对应的原始动作JSON创建`Assets/Resources/EditedAnimations/<id>.asset`草稿；重复导入会复用资产，不覆盖已有草稿或发布数据。游戏只读发布快照，未发布修改不会进入生产。

窗口可选择动作与步骤，以80ms原版节拍播放／逐步预览；检查左右朝向、装备换装、剑灵外观、攻击／身体／脚底框、动作位移与攻击／格挡标记。步骤可复制或删除，也能复制动作；复制帧默认成为独立帧，避免编辑时误改共享源帧。图层裁切与脚底尺寸可调整，并支持Unity Undo。

点击“校验并发布”先检查帧引用、裁切范围、变换值与框尺寸，再在编辑期保存所需Sprite并扩展目录内角色Prefab的帧片容量，最后保存发布快照。生产加载统一从`OriginalAssets.Json<OriginalAnimation>`读取发布内容，角色、武器换装和剑灵层共享该入口。h_00为原版等值样例，含57个动作、364帧。

动作可新增步骤和动作，但当前发布器保持已有图层数量与原动作结构；窗口只处理已登记精灵配置及其映射到的动作资源。没有精灵配置登记的额外特效动作、新骨骼布局和全新行为机制不在此窗口支持范围。扩展前先登记资源映射并调整生产加载／校验规则。发布校验防止无效草稿进入生产；发布后可运行“古剑 → 验证动作编辑与生产加载”，再按受影响战斗专项回归。

## 武器

| 字段 | 作用与约束 |
| --- | --- |
| `id / name / description` | 独立编号、名称和描述 |
| `grade / level` | 品级及等级门槛；原武器商店沿用 `grade < 3 && level <= 主角等级` 的上架条件 |
| `hp / attack / defense / hit / dodge / critical / durability` | 基础属性与耐久 |
| `buy / sell` | 购买、出售单价；沿用原版余额需严格大于购买总额的规则 |
| `skill` | 技能表编号，可引用新增技能；-1从随机池选取，-2表示无技能 |
| `customRules` | 开启显式强化配置；复制模板时自动开启 |
| `canReinforce / maxReinforcement` | 能否强化、强化上限0～9；费用沿用原规则，在+5及配置上限提升技能，+9属性翻倍 |
| `randomSkillIds` | 逗号分隔的技能编号池；空值沿用原随机技能范围 |
| `image / icon / iconSprite` | 原换装纹理列表、原图标引用、可选持久 Sprite 图标 |

复制武器后可以沿用原武器外观、换装层和掉落动画，再独立调整数值和技能。新增原创外观还要制作与角色换装布局匹配的纹理、裁切和已保存掉落资源，不能仅填一个任意图片名。原版ID强化约定集中在兼容属性；不必为新武器新增ID分支。

## 道具

复制模板自动将旧ID规则转换成显式配置。直接编辑旧表行时，可先点“将选中原版规则显式配置化”。

| 字段 | 作用与约束 |
| --- | --- |
| `customRules / effectKind` | 启用配置规则、选择效果类型 |
| `hp / durability` | 恢复气血／恢复耐久使用的数值 |
| `effectValue` | 剑灵经验、银两、主角升级、永久属性等效果参数 |
| `attributeIndex` | 永久属性槽0～5，沿用原版HP、AP、DP、命中、闪避、暴击六项顺序 |
| `randomSkillIds` | 洗技能的候选技能编号；逗号分隔，空值沿用原5～21技能池 |
| `consumeWholeStack` | 背包使用时消耗所选一叠，最多99件；不是清空该ID全部库存 |
| `immediateUseInShop` | 购买后直接应用效果，否则进入背包 |
| `shopMask` | 0不上架，1随身商店，2NPC道具商店，3两者 |
| `maxPurchaseQuantity` | 单次购买上限1～99；确认框调量及按住重复使用同一上限 |
| `specialPurchaseGroup` | -1不递增；0～6复用七个存档价格组，同组共享购买次数 |
| `priceIncreaseStep / priceCap` | 每次成功即时购买后的加价步长与上限；购买次数兼容原版，最多累计19次 |
| `buy / sell / iconSprite` | 基础单价、卖价、持久图标；保存配置时同步扩展道具掉落图标 |

当前支持效果：恢复气血、恢复耐久、提升武器技能、复活、修满活动武器、剑灵经验、银两、主角等级、永久属性、随机武器技能。它们共用现有玩法条件，例如剑灵经验仍要求剑灵存在且未到40级、升级仍有等级上限、复活仍走死亡动作状态。

整叠使用时，银两和剑灵经验按件数乘 `effectValue`；其他效果保留一次应用的语义。建议普通恢复药与强化类道具使用单件消耗。递增价格组只允许“购买后立即生效”的道具；随身商店仍为NPC单价的两倍。复制的新道具默认不共享原价格组，按需求显式指定。

新增药品可在背包和商店使用；剑灵自动用药、死亡自动复活的选药仍沿用原版ID策略，当前没有自动把所有新药加入优先级。

## 技能

选择原技能模板，复制新编号，修改名称、说明、品级、冷却、霸体伤害和公式。`customBehavior = true` 时，`behaviorId` 选择既有行为5～21；实际编号用于装备、查表、存档，行为编号用于原动作、施法类型、图标和特效。

攻击技能复用模板5～13，辅助技能复用14～21；伤害／修正／消耗的字符串公式沿用模板语法。可以新增数值和冷却不同的同类技能并配置到新武器，也可将复制技能切换到兼容的辅助行为。新动作结构、全新弹道或新状态机制仍需补代码及持久资源。

配置窗口会校验技能存在性、行为范围、公式解析和随机技能池引用。这里不是任意招式的可视化编辑器。

## 敌人

复制敌人时同步创建独立的 `EnemyDefinition`、`SpriteDefinition` 与角色 Prefab，并登记角色目录。修改敌人的成长系数、命中、闪避、视野、经验、银两和掉落表；攻击范围、伤害系数、霸体伤害及间隔的条目数量必须匹配。

敌方AI仍使用 `SpriteDefinition.behaviorId` 对应的原模板。`id` 是新敌人本身的身份，用于查表、生成和任务计数；`behaviorId` 用于原AI家族、Boss招式和弹体行为。复制的敌人保留原角色类型与动作布局；全新AI或动作布局需要新增实现。掉落表使用“概率0～100,内容编号”，多个条目用分号分隔，`0`表示无掉落；配置校验会检查掉落编号是否存在。

剧情生成例：`x30(9900,9004,"l",200,250,2)`，9900为在场实例号，9004为你实际创建的敌人定义号，坐标为像素；例中的9004不是工程自带内容。NPC交互／死亡回调继续通过 `x37` 配置。掉落表沿用模板字符串格式，引用新道具时先确认其掉落Prefab已保存。

## 地图：旧地图与新瓦片地图

52张原地图继续使用已保存的三层 SpriteRenderer 和原碰撞数据，保持原画面及剧情。新增区域可使用四层 Tilemap：地面、装饰、前景遮挡、阻挡。两类地图共用地图目录、正式加载器、剧情入口和原碰撞查询。

1. 打开“瓦片地图编辑器”，填写以字母开头、仅含字母／数字／下划线的地图编号，例如 `map_new_area`。设置行列数和格宽高；最多256×256格。点击“创建并登记新地图”。
2. 准备已导入的 Sprite，使用与像素坐标匹配的 Pixels Per Unit=1；像素画采用 Point 过滤、关闭压缩与 Mip Maps。选择“创建瓦片用 Sprite”，点“从 Sprite 创建持久瓦片”，保存 Tile 资产。
3. 选择地面／装饰／前景／阻挡层，选择瓦片画笔，点击或拖动网格绘制；勾选“擦除”后擦除，支持 Unity Undo。阻挡层只表示不可走，运行时不显示。
4. 点击“保存地图与碰撞”。地图保存到 `Assets/Resources/Maps/<地图编号>.prefab`，碰撞编辑期写入地图目录；地图切换或关闭窗口时，未保存编辑会提示保存。
5. 扩建现有新地图：加载其Prefab，增加上方行列数，点击“按上方尺寸扩建当前地图”，继续绘制并保存。现有坐标不移动；不支持缩小或直接改变已有格宽高。
6. 填写新阶段编号、名称与入口像素坐标，点击“为地图创建剧情入口与阶段布局”。工具保存 `Stories/<编号>.asset`、`Baked/Stages/<编号>.prefab`，登记扩展阶段及资源目录。用剧情调试器载入该编号可直接测试。

格坐标与像素坐标要区分：地图窗口的格 `(x,y)` 对应 Unity Tilemap `(x,-y-1)`；原剧情像素向右、向下为正。`x24`出口使用格坐标，`x26`主角入口、`x30`角色位置使用像素坐标。阻挡在保存时编译为原 `OriginalMap.cells[].blocked`，没有在运行时重建地图或改用另一套物理碰撞。

地图新阶段只生成最小入口脚本（场景名、加载地图、入口位置、stageID和加载完成）；出口、任务条件、NPC和战斗流程仍由开发者编写。小地图房间和世界旅行目的地需要另行登记，目前不会自动扩展原13区／174房间配置。新图块及地图美术也由开发者提供。

## 出口、入口和NPC事件

内容工作台可按地图定位所有关联阶段，进入“编辑出口 / 入口 / NPC 事件”。索引来自正式剧情资产，保留原条件、分支、步骤顺序和备注。编辑已有事件后精确写回相应指令；陈旧索引与不存在的目标会阻止覆盖。

增加新出口在剧情步骤中添加 `x24(格X,格Y,"目标脚本.s")`，入口用 `x26(像素X,像素Y,"r")`；双向往返需分别配置两个方向。新增NPC按既有阶段Prefab布局和 `x30/x37` 流程配置。修改剧情后重新生成事件索引，并执行“校验地图事件引用”。索引是编辑器派生数据，不替代运行剧情。

原包目前有8条出口引用指向2份缺失脚本：`1401_1400.s`、`1436_0.s`。工具显式报告，未编造补齐剧情；处理时需核对原资料或按新的剧情设计替换。

## 验证与边界

新增内容专项使用临时编号和独立存档，覆盖模板复制、引用校验、商店上限、缓存、重复导入保护、实际道具／技能／武器／敌人运行、新编号存读档、Tilemap正式加载与出口注册，完成后逐字节恢复生产数据库和资源目录并删除夹具。见 `Validation/content-extension-editor.json`、`Validation/content-extension-play.json` 与 `Validation/content-extension-batch.json`。

原战斗与商店按受影响专项回归；不将完整新档通关作为每次配置修改的默认测试。游戏正常难度全程、实体输入、全局音画逐帧对照和Android真机仍属于独立还原验收；本批不会增加历史95%的工作量估算。

当前结构可沿已有规则和配置入口继续扩建。技能能量／冷却／霸体／恢复已有独立运行状态，钱包与奖励生产入口已统一；施法效果、HP与死亡、全局存档恢复顺序和部分UI业务仍由主控协调，整体尚未完全解耦。详见 `工程优化与架构评估.md`。
