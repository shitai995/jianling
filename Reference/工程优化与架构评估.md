# 工程优化与架构评估

## 当前判断

目前已能通过配置窗口扩建武器、道具、技能和敌人，通过Tilemap窗口制作新地图并创建剧情阶段。原版行为继续兼容；新增同类内容复用现有规则。增加新的战斗机制、存档状态或菜单流程仍需要代码修改。内容入口更加集中，但核心玩法耦合度仍偏高。

2026-10-21优化前检查基线：54个运行时代码文件，其中38个通过partial共同组成GuJianGame，共7,238行。它们共享战斗、背包、装备、菜单、剧情等待和存档等私有状态。拆成多个文件没有建立独立模块。脚本执行器OriginalScriptMachine、文本标记等已有独立实现，可以保留。

| 范围 | 现状与影响 | 优化方向 |
| --- | --- | --- |
| 数据与固定资源 | 数据库、Sprite、角色和地图Prefab已保存；新增同类内容有入口 | 清晰的内容名称、引用检查和编辑入口 |
| 剧情 | VM独立；指令宿主直接修改主游戏共享状态，依赖event/stageID等约定 | 先统一剧情来源，再分离剧情命令与各玩法模块的交互 |
| 地图 | 工作台统一定位地图、阶段和NPC；原图层兼容，新Tilemap可保存与扩建，事件可定位及编辑 | 新区域的小地图／旅行登记和原创图块制作；复杂新触发机制按需求扩展 |
| 精灵与动作 | 保留图集拼帧、换装层、攻击框和80ms周期；动作编辑器已支持草稿、预览与校验发布 | 扩展新的动画家族及未登记特效动作仍需资产与生产接入 |
| 背包与道具交易 | ItemInventory拥有数量和堆叠，ItemTrading拥有报价和阶梯价格；各调用方已统一接入 | 保持统一读写入口，后续UI复用模块规则 |
| 装备实例与穿戴 | EquipmentInventory持有列表、选中身份、耐久／技能游戏写入口、强化与快照；EquipmentTrading持有报价确认；外观由主控协调 | 字段保留公开可序列化以兼容JsonUtility和实例创建；合体外观与属性应用仍由主控协调 |
| 耐久、修理与合体映射 | WeaponDurability持有剑灵耐久、合体模式及修理报价；普通剑写入委托EquipmentInventory，当前耐久直接映射普通实例或剑灵 | 合体外观、属性刷新与破剑演出仍由主控协调 |
| 战斗与属性 | CombatAttributeCalculator集中属性成长；CombatDamageCalculator集中伤害数值；SkillRuntime持有技能能量、冷却、霸体、恢复及待施法状态 | 主控仍处理施法条件、耐久消耗、效果应用、HP事件和刷新时序 |
| 存档 | version 3仍由主游戏保存文件和协调恢复；钱包、技能、HP、计时器及吸收状态有模块快照，并兼容缺失或null的旧快照；装备、成长、剑灵和技能恢复后统一计算属性并恢复HP，编辑工作流专项通过 | 全局文件和兼容版本仍由主控管理；逐系统核对其他临时状态生命周期 |
| 界面 | IMGUI绘制与业务操作混合，依赖手写坐标 | 界面读取显示数据、提交操作；逐页迁移到可编辑Prefab |
| 验证 | 有大量专项，但许多需要反射和预置整场游戏 | 抽离后的业务模块与界面通过相同入口调用，保留必要的GameView集成验证 |

背包、道具交易、装备实例列表、穿戴身份、耐久映射、钱包、奖励提交和武器报价已有独立入口；武器／道具／技能／敌人有独立扩展表与配置窗口，并通过统一查表、跨表校验和持久图标／Prefab登记接入，不需要另建平行配置系统。属性与伤害公式由无状态计算模块提供。`SkillRuntime`拥有技能能量、冷却、霸体、恢复及待施法数据，`RewardService`已覆盖现有剧情、掉落、商城与礼包奖励生产调用。version 3存档仍由主控统筹，但钱包、技能、HP、计时器和吸收状态以可序列化快照保存；显式缺失或null的嵌套快照会回退旧字段。最新编辑工作流确认装备、成长、剑灵和技能状态恢复后再计算属性与恢复HP，报告7项通过。动作编辑器从原JSON建立原生草稿，发布后由统一生产读取入口加载。装备耐久与技能的运行时业务写入已集中到`EquipmentInventory`；公开字段仍用于Unity序列化和实例初始化。施法效果、HP表现、属性应用、外观演出和UI业务仍有主控协调，整体耦合度尚未低。

## 第一批已落地：内容编辑来源

- 新增菜单“古剑 → 内容 → 内容工作台”，按名称或编号查找地图、剧情和精灵。地图可定位碰撞、布局与关联剧情；精灵可定位Prefab、动作数据及图集。
- 768份原剧情转换为Assets/Resources/Stories下的StorySequence资产，保留25,715条原指令。资产可填写显示名称和开发备注，逐步骤修改，支持Unity撤销和保存。
- OriginalAssets.Script是运行时、布局准备及剧情验证共用的读取入口；优先读取剧情资产，未迁移的旧内容仍可从JSON读取。执行器获得独立步骤快照。
- “补充剧情资产”只创建缺少的资产，保留已编辑资产。原JSON和阅读文本保留作导入与行为核对；修改它们不会覆盖已存在的剧情资产。
- 剧情调试器已接入同一读取入口，支持发现只有原生剧情资产的新剧情。
- 本批没有把步骤转换成完整的可视化条件图，也没有完成核心玩法状态抽离。当前指令步骤仍采用原语法，原版时序与分支语义继续保留。

## 第二批已落地：背包与道具交易（2026-10-21）

- `ItemInventory`独立持有库存，不再向调用方暴露可写字典。负责增减、99件堆叠、选中叠限额、排序行、快照与恢复；205件仍显示99／99／7。
- `ItemTrading`独立持有七种特殊道具的购买次数，集中处理报价、数量循环、购买条件、阶梯价格、成交与失败结果。确认时重新检查商店、库存、价格及剑灵等级；同一报价只可确认一次。
- 掉落、奖励、礼包、剧情`x51/x4A/x4B`、用药、丢弃、菜单和商店均经统一库存入口。原版99件批量用药、特殊道具购买即用、余额须严格大于总价、随身商店双倍购买价和选中叠出售规则已保留。
- `SaveData`保留version 3和原`itemIds/itemCounts/specialItemPurchases`字段；主控负责文件和恢复顺序，模块提供快照与恢复。零库存不再写入快照；旧档中的零条目和缺少可选价格字段仍可读取。
- 原来通过反射强转库存字典的四份专项验证已改为使用生产模块入口。新增“古剑 → 验证背包与交易模块”和“古剑 → 验证背包剧情与存档接入”。
- 本批没有新增运行时固定资源、节点、图像生成或第三方依赖。Unity编辑器内定向验证7份报告、59组通过，见[批次汇总](Validation/inventory-trading-batch.json)。这些是边界及集成检查，物理鼠标／键盘点击和正常难度全程仍待验收。

第二批结束时的状态归属（装备后续变化见第三批）：

| 模块／位置 | 当前职责 | 仍需处理 |
| --- | --- | --- |
| ItemInventory | 数量、堆叠、增减、库存快照 | 持续由所有新功能复用 |
| ItemTrading | 道具报价、数量、价格增长与成交规则 | 武器交易仍随装备模块处理 |
| GuJianGame／各partial | 金钱、物品效果、装备实例、穿戴、战斗、剧情与UI协调 | 金钱和跨系统效果尚未独立；不把本批视为整个核心已解耦 |
| SaveData／Save／Load | 兼容旧字段、存档文件与系统恢复顺序 | 后续明确其他模块快照与恢复职责 |

## 第三批已落地：装备实例与穿戴身份（2026-10-21）

- `EquipmentInventory`持有装备列表与当前实例，向UI提供只读列表。选中索引由对象身份计算，移除前面的条目后不需要在商店和剑灵代码中分别修正索引。
- 奖励、掉落、礼包和武器购买经过`Add`；出售与吞噬经过`TryRemove`，拒绝移除当前穿戴对象或已经失效的实例。剧情`x54`走`RemoveFirst`，保留原版首次匹配和ID-0备用剑规则；`x55`仍选择最后一个同ID实例。
- 强化入口集中检查所属实例、上限、费用和耐久比例；+5／+9技能升级、+9属性翻倍及原费用保留。穿戴切换后的外观、技能冷却、合体与属性刷新继续由主控协调。
- 存档仍使用version 3的`equipment/equippedIndex`；模块复制强化、耐久和技能字段生成快照，恢复也复制数据且不重掷随机技能。加载完成时应用保存的穿戴状态，避免用旧的活动耐久覆盖已恢复的武器。
- 新增“古剑 → 验证装备实例模块”和“古剑 → 验证装备剧情与存档接入”；12份既有验证中的装备列表反射改为生产模块入口。18份报告共177组通过，覆盖原版强化教程、剑灵重置及换剑检查点真实Update流程；正式存档与全局礼包文件哈希保持不变。专项与受影响回归见[本批汇总](Validation/equipment-ownership-batch.json)。
- 本批完成的是列表归属、穿戴身份、结构变更保护、强化入口和快照；`EquipmentInstance`的耐久／技能等字段仍可写，武器商店的等级与报价检查、修理、战斗消耗和属性组合仍在主控。本批不表示装备与战斗已经完全解耦。

## 第四批已落地：耐久、修理与合体映射（2026-10-22）

- `WeaponDurability`持有剑灵耐久、合体模式与修理报价；`Current`直接读写当前普通实例或剑灵，不再保存第二份活动耐久。换剑、强化和保存无需手工同步副本。
- 技能、崩击、敌方耐久攻击、用药、修满及破剑接入模块；破剑动画、属性刷新及合体外观仍由主控按原时序协调。合体仍要求耐久严格大于上限的10%，进入扣一次，解除不扣；无限耐久保留零耐久合体行为。
- 全普通武器修理按总缺口和受损件数报价，确认时使用先前缓存报价；余额恰好等于费用可成交，不修剑灵。原`x87`未先执行`x89`时初始费用为零的语义保留。
- 保留version 3及`durability/spiritDurability/integrated/equipment/equippedIndex`字段；读档先恢复普通实例与合体模式，再恢复活动耐久，避免合体值覆盖普通剑。专项覆盖普通剑37耐久、合体211耐久存读档并解除后仍为37。
- Unity编译成功，19份定向报告共165组通过，含真实后台破剑暂停／恢复、剑灵等级比例及原剧情重置换剑检查点。三个正式玩家数据文件哈希不变，见[本批汇总](Validation/durability-integration-batch.json)。本批使用模块与受控集成验证，未重跑完整主线，未打包。
- 本批消除了活动耐久副本及修理／合体映射规则的重复实现；普通实例字段仍可写，技能、伤害、金钱及表现协调没有全部解耦。未新增运行时固定资源生成或第三方依赖。

## 第五批已落地：属性计算（2026-10-22）

- `CombatAttributeCalculator`集中主角成长、装备／永久加成、剑灵七项成长、三类敌人成长分段及连击AP规则，返回`CombatAttributes`值快照。输入来自实时数据库和当前状态，计算不修改输入，不缓存表行或结果，不持有角色／装备引用。
- `RefreshAttributes`、剑灵查询、连击命中及HUD基数复用计算入口。主控继续决定刷新时机、应用HP比例／取整、回血、死亡标记、霸体、动作与表现；永久加成、剑灵经验和连击计数仍归现有状态所有者。本批收拢公式，没有把属性快照变成第二份持久状态。
- 保留刷新AP与命中AP不同的原规则：永久主角AP参与刷新倍率，但不参与命中重算；剑灵吞噬AP参与最终AP，但从命中倍率基数扣除。保留十击最低+1、普通零耐久仍保留AP、暴击仅上限1000、敌人99／100级分段及HP比例四舍五入。合体零耐久门控沿用本批修改前行为，没有另改平衡。
- Unity编译成功，15份定向报告共113组通过；含独立数值边界、三类真实敌人19／20／99／100／150级黄金值、普通／合体接入、实时成长编辑恢复及剑灵原剧情真实Update。三个正式玩家数据文件哈希不变，见[本批汇总](Validation/attribute-calculation-batch.json)。未重跑完整主线，未打包；编辑器保持后台标题待机。
- 仍需处理技能与伤害结算、可写实例字段、金钱、存档协调和UI业务混合。未增加第三方依赖或运行时固定资源生成，还原百分比不因架构整理上调。

## 第六批已落地：伤害数值结算（2026-10-22）

- 新增无状态 `CombatDamageCalculator`，集中主角基础伤害、敌人基础伤害、随机浮动、暴击结果和主角／敌方闪避概率。随机函数由宿主传入，保留原抽样次数、调用顺序和区间上界；模块不持有角色、装备、场景或持久状态。
- 普通攻击与技能、葬剑命中统一使用 `RoleHit`；敌人近战和弹体统一使用 `EnemyHit`。弹体仍在发射时计算并保存伤害，命中时不重新读取施放者属性，也不继承施放者暴击；崩击继续使用普通武器最大耐久三倍并跳过浮动。
- Boss 绝杀复用基础公式和浮动入口，半血、吸血、破剑、捕获分段、护血和演出时序继续留在 `OriginalCritical` 宿主。主控继续负责几何命中、连击、霸体、扣血、死亡、剧情、能量、受击、声音和特效。
- Unity 编译成功；伤害模块、数据边界、攻击技能、连击崩击、辅助技能、Boss 家族、暴击反馈、破剑、战斗反馈、敌方气血、HUD、弹体和战斗行为共13份报告133组通过，见[批次汇总](Validation/damage-calculation-batch.json)。正式三个玩家数据文件哈希不变，未打包，编辑器恢复标题并保持后台。
- 本批只减少公式重复和随机边界耦合，没有迁移技能施放、资源／冷却、HP事件、可写装备字段、金钱或UI业务；未新增运行时固定资源和第三方依赖，还原工作量估算仍保持95/100。

## 第七批已落地：地图事件与内容扩建（2026-10-22）

- `MapEventSetup / MapEventCatalog`建立编辑器派生索引，从正式剧情解析入口、出口和角色回调。保存只替换对应原指令，保护源行、条件、空白与备注，并提供Unity Undo。52张原地图、209阶段均保留；报告明确列出8条指向两份缺失原脚本的出口。
- `ContentConfiguration`统一模板复制、持久资源登记及跨表校验。数据库基线与扩展表共用查表入口，合并表缓存按数组引用失效，避免每帧合并分配；导入仅补缺失原记录，不覆盖已有编辑。
- 道具规则从新ID中分离为效果类型、参数、商店范围和购买上限；武器强化、技能池可配置。技能与敌人将内容身份与既有行为模板分开，新编号可以复用原动作、特效、AI与数值结算。原版兼容规则仍集中保留。
- `EditableTilemap / TilemapAuthoring`建立四层持久地图；绘制、扩建、碰撞编译及剧情／阶段Prefab创建都在编辑期完成。运行时沿用原目录、加载器、碰撞与VM，不增加第二套移动系统。
- 验证包含地图事件编辑、新编号实际用药／装备／施法／生成、独立存读档和正式Tilemap加载；10份报告共110组通过，本批报告与源码校验和见[汇总](Validation/content-extension-batch.json)。操作及限制见[扩建指南](内容扩建与配置指南.md)。
- 该批降低常规内容扩建对ID条件分支的依赖，没有把资源／冷却、HP／死亡、金钱、存档协调和UI业务全部拆离主控。新战斗机制仍需代码；任意原创动作、旧地图全量转换和世界旅行自动扩容不在本批完成范围。

## 第八批已落地：钱包、奖励与HP生命周期快照（2026-10-22）

- `Wallet`集中余额读取、扣款、加款和快照恢复。精确余额扣款、拒绝负数变更、溢出时余额不变及快照往返均通过。
