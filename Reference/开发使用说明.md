# Unity 工程开发入口

用 Unity 2022.3.62f3 打开 `UnityProject`，启动场景为 `Assets/Scenes/GuJian.unity`。直接 Play 显示标题；正式存档和各验证存档分开保存。

## 编辑固定内容

- 统一入口：菜单“古剑 → 内容 → 内容工作台”，可搜索地图、剧情、精灵名称或编号，定位现有地图Prefab、碰撞、NPC布局、剧情资产、角色Prefab和动作图集。

- 内容扩建：菜单“古剑 → 内容 → 武器道具技能敌人配置”支持检索、复制独立编号、配置既有效果／行为与跨表校验；“古剑 → 内容 → 瓦片地图编辑器”支持新地图绘制、增加行列、碰撞保存及创建剧情阶段。完整操作和字段表见[内容扩建与配置指南](内容扩建与配置指南.md)。
- 地图事件：内容工作台中选择地图，点“编辑出口 / 入口 / NPC 事件”；可精确修改已有事件并写回剧情资产。新增指令后重新生成地图事件索引并校验引用；原包8条出口引用缺少两个目标脚本，报告见`Validation/map-events.json`。

- 地图层：打开 `Assets/Resources/Baked/Maps` 的地图 Prefab。52 张地图的三个 SpriteRenderer 图层均已保存。
- 角色遮挡：Actors／Effects／Drops Prefab 保存 SortingGroup；运行时按原地图层、脚底高度与主角偏移排序。39种战斗角色保存50个数字 Renderer、1个闪避 Renderer和1个普通敌人血条 Renderer，使用 `OriginalUiLayout.asset` 中40个数字裁切、闪避 Sprite和20档21×5血条 Sprite。退出 Play 后可运行“古剑 → 补充角色整体排序与战斗数字节点（保留已有编辑）”补缺；已有节点和图集引用保留。
- 固定物件：打开 `Assets/Resources/Baked/Stages` 中对应入口的 Prefab；调整嵌套物件 Transform。脚本激活时读取保存的位置。
- 特殊敌人光环：10种type11角色Prefab中的`Enemy back effect`嵌套原`s_36`特效；原动作0为单帧。退出Play后可用“古剑 → 补充特殊敌人背后特效（保留已有编辑）”补齐缺失引用与裁切；已有光环节点保留。
- 碰撞：菜单“古剑 → 地图碰撞编辑器”，选择地图，拖动绘制阻挡／通行，⌘Z 撤销，“保存碰撞”写入 `OriginalAssetCatalog.asset`。同地图所有场景共享碰撞。导出 JSON 后可导入同标识／尺寸的碰撞；导入只更新 blocked，不改动地图图像或 Prefab 布局。
- 数值：选择 `Assets/Resources/OriginalDatabase.asset`，直接编辑装备、道具、敌人、技能以及主角／剑灵／敌人成长数组。三个成长表按表名读取，Inspector 修改实际参与属性计算。
- 界面：`OriginalUiLayout.asset` 保存 HUD、原版35组菜单动作、8张菜单图集、连击三档／数字、四种战斗数字与闪避图、技能快捷图集、世界地图、立绘和窗口坐标，以及场景名演出的字号／上移高度，以及破剑四帧动作2／破损静态动作4；`OriginalTouchLayout.asset` 保存11个操作区、原方向盘、普通／按下纹理、透明度及位置。
- 区域小地图：`Assets/Resources/OriginalMiniMapLayout.asset`保存13区域、174房间的位置、四向出口和标记引用，可在Inspector编辑。M或右上地图键打开，M／Esc／返回键关闭；该界面与世界旅行菜单独立。原始静态表由`Tools/export_minimap.py`导出到`Reference/minimap.json`，只在编辑器补资产时读取。
- 音频：启动场景及 `GuJianGame.prefab` 内的 AudioSource 已保存，可调整引用和音量。

## 修改脚本和动作

运行时剧情优先来自 `Assets/Resources/Stories/*.asset` 的 `StorySequence`，现有768份原剧情已迁移。通过内容工作台选择剧情，点“编辑剧情步骤”，在Inspector修改显示名称、开发备注和步骤，保存后重新开局或载入相关剧情。步骤保留原语法、原执行顺序和原编号，支持Unity撤销。`OriginalAssets.Script`是共用读取入口；缺少剧情资产时兼容读取 `Assets/Resources/Original/Scripts/*.json`。

新增剧情：在 `Assets/Resources/Stories` 中通过创建菜单“古剑 → 剧情序列”建立资产，资产文件名与脚本标识保持一致；填写步骤后可由原 `x20` 或剧情调试器调用。原 JSON 与 `Original/script/*.txt` 用于导入和核对，修改它们不会覆盖已存在的剧情资产。菜单“古剑 → 内容 → 补充剧情资产（保留已有编辑）”仅补充缺少的资产。

动作来自 `Assets/Resources/Original/Animations`；图集位于 Original/action、Original/key 和 Original/pic。图像以已有纹理引用更新。每次新游戏／读取存档会清理解析缓存，重新读取脚本和动作数据。

如果动作裁切或拼帧数量增加，退出 Play 后运行“古剑 → 生成缺少的预制资源（保留已有编辑）”。该工具添加新裁切、补充缺失 Prefab，并在必要时扩充已有角色的拼帧节点；已有布局和已有 Sprite 保留。请在修改动作裁切时同步对应 JSON。新 Sprite、固定节点和组件在编辑器生成并保存。

“从原版 JSON 导入数据库”只按编号／剧情标识补缺失的原版记录，保留已有数值、规则和扩展内容；成长表仅在空表时初始化。若主要在 Inspector 编辑数值，直接保存数据库即可。

## 背包与道具交易开发

`GuJianGame.Inventory`提供唯一的库存状态，类型为`ItemInventory`。奖励或掉落使用`Add(id, quantity)`；需要严格数量的消耗使用`TryRemove(id, quantity, stack)`并检查返回值；原剧情的不足清零规则使用`RemoveUpTo`。`Count/StackCount/StackQuantity/StackRows`读取数量及每叠99件的显示数据。`Capture`返回独立快照，`Restore`负责恢复聚合数量；调用方不能直接写库存字典。

`GuJianGame.ItemTrading`集中持有道具阶梯价格和报价规则。普通游戏界面继续调用`SelectItemTrade/SetTradeQuantity/ConfirmTrade/CancelTrade`，由主控检查商店／预览上下文后接入交易模块；不要在绘制代码中再次扣钱、改库存或累计购买次数。武器实例交易、道具实际效果和金钱当前仍由主控协调。

新增道具通过配置窗口复制模板，设置`effectKind`、恢复量／效果参数、商店掩码、单次购买上限和即时使用等字段；既有十类效果无需增加ID分支。全新物品机制仍需要扩展效果实现。背包模块只管理数量，不推断道具效果和地图状态；自动用药仍按原版选药策略。存档继续使用version 3的旧字段，主控把库存和价格快照写入文件。

菜单“古剑 → 验证背包与交易模块”无需进入场景即可检查库存与交易规则；“古剑 → 验证背包剧情与存档接入”在独立Play会话检查真实VM、道具使用和存读档，使用单独验证存档。改动菜单交互时同时运行原道具商店／菜单状态专项；改动掉落或复活时选择相应专项。

## 装备实例与穿戴开发

`GuJianGame.Equipment`是只读列表，`EquipmentBag`持有列表结构及当前实例。奖励和掉落通过`Add(instance)`加入独立装备对象；同一个对象不能占据两个位置。出售／吞噬通过`TryRemove(instance)`，成功前需确认返回值；它会拒绝当前穿戴对象和失效引用。移除前面条目后，`EquippedIndex`从当前对象计算，调用方不要手动改索引。

游戏中的穿戴使用现有`SelectEquipment/Equip`协调入口，除了模块选中状态，还需同步角色图像、技能、耐久和属性；请勿在UI里只调用模块`TrySelect`就当作完整穿戴完成。模块`TrySelect`用于状态操作和独立验证。脚本的移除备用剑规则已经集中到`RemoveFirst`。

强化通过`ReinforceEquipment`协调入口，模块检查实例归属、上限和费用并保留原耐久比例。`Capture/Restore`复制实例字段用于存档，读取快照不共享可写对象，也不重置随机技能。当前耐久已经直接映射实例／剑灵，不再另存副本；实例字段依然可写，属性和伤害公式已接入下述计算模块；技能资源／冷却和HP事件仍属后续工作。

“验证装备实例模块”可独立运行；“验证装备剧情与存档接入”需独立Play会话，覆盖原VM的重复武器、穿戴／移除及真实存读档。商店／吞噬／强化UI改动还应运行对应集成专项。

## 耐久、修理与合体开发

`GuJianGame.Weapons`为`WeaponDurability`。普通耐久保存在`EquipmentInstance.durability`，剑灵耐久与合体模式分别由`Spirit/Integrated`提供只读访问。`Current`直接映射活动来源；旧`game.durability`属性转发到这里，不要再维护另一份当前耐久。没有选中普通武器时只提供默认读取值50，写入会抛异常；开局应先初始化装备。

正常玩法使用`SetCurrent(value, spiritMaximum)`、`SetSpirit(value, maximum)`限制上下界，`Spend(amount)`扣除并限制下界，`RefillCurrent(spiritMaximum)`修满活动来源。`Current`写入与`Restore`保留原整数值，供存档兼容和原流程适配；它们不负责属性刷新或演出。破坏普通武器使用`BreakOrdinary`，合体时不会误清剑灵耐久。需要破剑动画、用药反馈或属性刷新时，仍通过主控已有协调入口完成。

合体由主控`ToggleIntegrate`协调。模块`TryToggle`只检查严格10%门槛、扣除进入费用和切换模式，不负责角色存在检查、换装、动作、技能、冷却或属性。不要在UI中只调用`TryToggle`就当作完成合体。`QuoteRepair`缓存全普通武器报价，`TryRepair(ref money)`使用该报价修满普通装备，允许余额恰好等于费用，剑灵保持不变；保留原`x89`报价／`x87`确认语义，不在确认时重新报价。

存档仍为version 3。先恢复装备快照和选中对象，再恢复`Spirit/Integrated`，最后恢复活动`durability`，避免合体耐久写入普通剑；主控`Load`已经按此顺序接入。

菜单“古剑 → 验证武器耐久模块”检查映射、合体边界及修理；“古剑 → 验证耐久合体存档接入”在独立Play会话检查普通／合体存读档和剧情修理，使用独立验证文件。修改耐久消耗时选择对应技能／崩击／破剑专项，修改剑灵成长时选择剑灵等级专项；不默认重跑整条主线。本批19份报告共165组检查见[汇总](Validation/durability-integration-batch.json)。

## 属性与成长开发

`CombatAttributeCalculator`接收实时`AttributeDefinition`、等级、装备值快照与加成数组，返回`CombatAttributes`值快照。主角组合用`Role`，剑灵全组／单项用`Spirit/SpiritValue`，敌人用`Enemy`；普通装备值仍由`EquipmentInstance`计算。修改数值继续编辑`OriginalDatabase.asset`，不另建缓存或把原JSON作为运行时替代来源。

`Role`用于刷新属性；命中与清连击使用`ComboAttack`，HUD基数用`ComboBaseAttack`。两条AP路径保留原加成差异，不应统一替换：永久主角AP仅参与刷新组合；剑灵吞噬AP参与最终AP，但不参与命中倍率基数。零耐久时普通剑AP仍贡献，其他装备属性由现有门控控制。

计算模块不负责升级、扣耐久、刷新时机、回血、死亡、动作或UI。业务仍调用主控已有协调入口，再由其按原时机应用结果；不要把快照长期缓存或只算快照就当作完成穿戴／合体。原HP比例恢复继续由`RefreshAttributes`使用float与`Mathf.RoundToInt`完成，永久加成和连击计数也不迁入计算模块。

“古剑 → 验证属性计算模块”可在Edit模式运行，覆盖固定预期与边界；“古剑 → 验证属性计算战斗接入”需独立Play会话，核对普通／合体、三类敌人成长及实时数据库读取。修改技能／连击／吞噬时再选择对应专项；`SpiritLevelValidation`含异步真实Update，应等待完成后再运行其他fixture。本批15份报告共113组通过，见[汇总](Validation/attribute-calculation-batch.json)。

## 伤害结算开发

`CombatDamageCalculator`只计算数值，不访问角色或场景。`RoleBaseDamage`保留主角技能公式和等级／受伤倍率，`RoleHit`按原顺序执行浮动与暴击；技能4使用普通装备最大耐久三倍并跳过浮动。`EnemyBaseDamage`和`EnemyHit`保留敌方整数运算、攻击模式系数、最小伤害1及发弹时快照语义。`DodgeChance`保留主角10～90与敌人仅上限90的非对称范围。

随机函数必须由调用方传入 `UnityEngine.Random.Range`，不要在模块内新增随机源或缓存结果。修改公式时先运行“古剑 → 验证伤害计算模块”，再按影响范围独立运行攻击技能、连击崩击、敌方弹体、Boss 家族和战斗行为专项；含真实 `EditorApplication.update` 的专项完成前不要并行启动其他fixture。模块不负责技能资源／冷却、连击计数、霸体、HP、死亡、剧情、声音或特效，这些仍通过 `GuJianGame` 原有协调入口处理。

本批13份报告共133组通过，汇总见[damage-calculation-batch.json](Validation/damage-calculation-batch.json)。弹体和战斗行为报告必须检查UTC时间与`passed`字段，不能把旧的超时报告当作当前结果。

## 调试与验证

“古剑 → 剧情调试器”可选择209入口、指定起始事件及角色等级，定位相应布局和运行时剧情资产；使用单独预览存档。

退出正式游玩后，在单独 Play 会话运行验证菜单：

按本次改动的影响范围选择验证，不把完整主线作为每次小修改的默认检查：显示改动直接加载对应场景，执行取帧、像素和遮挡检查；战斗改动选择受影响招式、敌人与实际命中检查；剧情、转场、存档、运行生命周期等跨模块改动或最终验收时才运行连续主线。保留每份报告的源码与资源校验和，后续无相关改动则复用已有证据。验证中发现新问题后只重跑受影响检查，修复通过后再决定是否需要扩大范围。

- “验证普通敌人受击血条”：原type9／11受击状态、20档整数宽度、真实命中及动作自然结束。`EnemyHealthValidation.RunLive()`检查后台菜单／冻结／恢复；`PrepareVisuals()`／`CaptureVisuals()`与`PrepareMapVisuals()`／`CaptureMapVisuals()`分别取血量边界和桥栏遮挡画面，准备与拍摄之间保留一次编辑器更新。`Tools/validation/check_enemy_health.py`复验颜色、位置、整数截断及前景alpha遮挡。
- “验证特殊敌人背后光环”：10种实际生成、原脚底居中、朝向／隐藏规则、层级及固定资源复用。`EnemyBackEffectValidation.PrepareVisuals()`／`CaptureVisuals()`取普通、下层角色遮挡和绝杀隐藏画面；`Tools/validation/check_enemy_aura.py`复验对应像素。

- “验证新档至结局连续主线”：一次新游戏、按原 NPC 交互与出口，从开场到原版结局；中途真实保存和读回。敌人任务使用低血量靶子，Boss 使用生产伤害入口，明确用于剧情连通验收。
- “验证正常属性与自主 AI 实战”：六种敌人，以原始属性、开启 AI 和碰撞移动，模拟普通操作；不改写战斗中血量，不直接调用 Damage。
- “验证编辑碰撞、计时存档与菜单资源”：临时编辑并恢复碰撞／成长数据；验证计时器、剑灵恢复节拍、吞噬演出与菜单资源引用。
- “验证触屏资源与区域小地图”：核对持久图集、5帧方向数据、原图尺寸、自定义编辑保留、13区打开／返回和普攻优先交谈。退出Play后，“补充操作布局与音效组件（保留已有编辑）”可补齐缺失引用。
- “验证连击冷却与EP界面反馈”：生产命中／真实角色周期、首次满EP六帧、17技能图标、冷却与菜单暂停。截图专项与取帧入口见`Assets/Editor/HudFeedbackValidation.cs`；截图fixture会改变当前游玩状态，应单独运行。
- “验证场景名滑入与停留”：场景名`x4C`的滑入、逐像素上移、停留、重启和清理。`StageInfoValidation.RunLive()`另验证真实后台Update；`PrepareVisuals()`／`CaptureVisuals()`用于冻结场景四阶段取帧。
- “验证伤害数字闪避与气血尾条”：生产命中、十周期寿命、封顶恢复量、Boss尾条和药品清理。`CombatFeedbackValidation.RunLive()`验证真实后台周期；`PrepareVisuals()`／`CaptureVisuals()`用于数字、闪避、尾条取帧。
- “验证角色整体排序与战斗反馈遮挡”：原脚底高度、主角+6、四地图层、持久节点、隐藏规则及技能／绝杀分组。`WorldPresentationValidation.PrepareVisuals()`／`CaptureVisuals()`和`PrepareMapVisuals()`／`CaptureMapVisuals()`分别取角色、真实桥栏遮挡；准备与取帧分开一次编辑器更新，让旧场景完成销毁。取帧器在同步Render前更新SortingGroup缓存。`Tools/validation/check_world_presentation.py`复验像素并生成对照图，需Pillow。
- “验证破剑动画暂停与敌方耐久攻击”：真实技能／崩击／葬剑／Boss／天草耐久攻击、整包修理和存档。`SwordBreakValidation.RunLive()`验证后台冻结及自然恢复；`PrepareVisuals()`／`CaptureVisuals()`取初始、四帧及破损静态。图像复验可运行`Tools/validation/check_sword_break.py`，需Pillow。
- 其他专项分别覆盖19种支线、15 Boss 家族、技能、交易、强化、背包、预制资源及独立应用。

报告保存在 `Reference/Validation`。各验证使用独立 validation 文件，避免覆盖正式进度。

## 平台

当前验证只使用最小化的Unity编辑器GameView，固定窗口状态，后台运行。

历史macOS 独立应用位于 `UnityProject/Builds/macOS/古剑魂梦.app`。Development 构建支持 `--gujian-smoke <报告绝对路径>`；正常双击进入标题。

当前编辑器未安装 Android Build Support，尚无 Android 包或真机验收。后续安装该 Unity 版本的 Android 模块及 SDK／NDK／JDK 后，可选择 Android 平台构建；手机输入、字体、音频和性能需实际设备复核。
